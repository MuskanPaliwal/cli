*New findings*

1. *An appended trailer can unlink a commit* (cmd/entire/cli/trailers/trailers.go:438).

• *Mechanism:* appendTrailerLine only joins a final paragraph made purely of trailers. The readers also accept mixed blocks and skip comment lines..
• *Effect:* the OPF rewrite (manual_commit_opf_rewrite.go:575) can add Entire-OPF-Applied: true as a new paragraph. That paragraph becomes the final block and pushes the existing Entire-Checkpoint trailer out of it. Attach then treats the commit as unlinked and rewrites it again..
• *Fix:* make the appender use the same block rules as FinalCheckpointTrailers..

2. *Post-commit and the readers disagree on a moved trailer* (manual_commit_provenance.go:258). When the user types body text below the trailer, post-commit still condenses into X. Attach sees no final-block trailer and adds a second one (Y). explain --generate refuses the commit, and a later amend doesn't keep X. The PR's doc admits this one.

3. *A commented-out trailer still counts* (manual_commit_provenance.go:258). The moved-trailer fallback uses the unanchored ParseAllCheckpoints regex. Under a cleanup mode that keeps comments, a user who unlinks the commit by writing # Entire-Checkpoint: X still gets the session condensed into X.

4. *Squash and redo inheritance still scan the whole message* (manual_commit_hooks.go:727, manual_commit_redo.go:132). After git merge --squash and an editor commit, the squashed commits' trailers are indented in the body. They count as already present, so nothing goes into the final block. With no new session content, the squash commit ends up with no final-block link. Documented as a limitation.

5. *Some explain paths still read the first ID* (explain.go:1713, 1731, 2471). The branch listing and the --checkpoint commit search still use ParseCheckpoint. On a squash commit with [X inherited, Y stamped], entire explain <sha> shows Y, the branch listing shows X, and explain --checkpoint Y finds no commit. The comment at checkpoint_api_reader.go:371 is now out of date. Documented as a limitation.

6. *A user-exported GIT_EDITOR=: brings back the trailer-only commit.* Editor detection treats it as "no editor", so a message saved untouched is recorded as just Entire-Checkpoint: X. With -v, the trailer goes below the diff and git discards it. Documented as a limitation.

7. *The prompt leaks into history under commit.cleanup=whitespace* (manual_commit_hooks.go:611). The explanation comment, including # Last Prompt: <user prompt>, is still written when git keeps comment lines. git then records it in the commit permanently. I'd rank this highest of the undocumented ones, because it puts prompt text into git history.

8. *A cached error can disable a whole hook* (hooks.go:72, manual_commit_hooks.go:3061). GetGitDir and gitCommentConfig cache their result for the rest of the hook using whichever ctx calls first. If that first call runs under a cancelled or expired budget ctx, the error is cached. Every later marker read and write then silently returns nothing.

9. *The trailer regex misses Key : value* (trailers.go:410). git allows whitespace before the colon, so a block like Reviewed-by : Bob plus Entire-Checkpoint: X is rejected, and prepare stamps a duplicate trailer.

10. *Extra hook latency* (manual_commit_provenance.go:233). recordStampedTrailer opens the repo again and re-resolves the parent commits, and commit-msg now runs a git config on every linked commit.

*Not re-checked:* GitHub squash-merge bodies (round 1, #6), where every squashed commit's trailer ends up in the final block, are likely still affected; this round didn't raise them and I didn't check. The hard-wrap note (round 1, #10) I'm dropping, because sessions-and-checkpoints.md itself is wrapped at 80 columns and the new text matches it.

I'd fix #7 and #8 before merging; neither is documented and both can silently go wrong. #1 is the same "use one block rule everywhere" problem as before, now on the write side. #2 to #6 are limitations the author has documented, so whether to accept them is a call for you or the author.
