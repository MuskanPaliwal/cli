The real new risks are listed below: JSON outranking prose, the last-line-only parse, and lenient unmarshalling.
  
  ## MUST
  
  1. **Combined-prose fallback parses only the last reviewer's JSON.** `combinedReviewNarratives` (review/cmd.go:1637-1650) concatenates reviewers, and `reviewTrailFindingInputsFromJSON` reads only `lastNonEmptyLine` (review_bridge.go:116, 223). Once every reviewer is told to end with JSON, the design's step 3 "otherwise post combined prose" ends with the last reviewer's JSON. If that line is `{"comments":[]}`, everyone else's findings are dropped. A single injected or compromised reviewer that happens to run last can silence the run. The bypassed path must skip the last-line JSON parse, or parse each narrative on its own.
  
  2. **Empty JSON must not outrank contradicting prose.** In the design, `comments: []` beats the prose, and only the narrow `[high]/[medium]/[low]` bullet net (step 4) can override it. Treat the result as clean only when all of these hold:

     - the prose has no top-level bullet, at any indent, tagged or not;
     - the verdict line does not say "request changes".
     Any mismatch should fail closed and post the prose.
  
  3. **Lenient unmarshalling turns malformed JSON into "clean".**

     - Require `comments` to be a JSON array (check with `json.RawMessage`).
     - If any entry has an empty or whitespace body, reject the payload as invalid and fall back to prose rather than skipping the entry.
