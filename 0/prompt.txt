## JSON5 feedback

  The concern is valid. The current CLI parses runner files with Go’s strict encoding/json: cmd/entire/cli/runner_prompt.go:88.

  I would separate the request into two product needs:

  - JSON5 helps configuration ergonomics: comments, trailing commas, unquoted keys.
  - JSON5 does not provide particularly good preserved multiline prompt literals. A referenced .md prompt file, TOML multiline string, or YAML block scalar would solve that more cleanly.

  For example, an especially maintainable design would be:

  {
    "id": "trail-correctness",
    "prompt": {
      "file": "prompts/trail-correctness.md"
    }
  }

  That keeps machine configuration structured while making long prompts pleasant to review and diff. what does this feedback was about?
