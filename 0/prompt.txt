`**Make `entire doctor` add the missing hook timeouts**

`entire enable` adds the new timeouts to existing installs, but people who already have Entire set up have no reason to run `enable` again. Doctor doesn't help either: `checkHookDrift` (`cmd/entire/cli/doctor.go`) relies on `CheckHookConfig`, which never looks at timeouts, so an install without them shows `✓ Claude Code hook config: OK`. Most existing users would therefore keep the old behaviour, where Claude Code waits up to 600s on a stalled hook.

Please add a doctor check that fills in the missing timeouts without asking, like `checkRetiredDenyRule` does for the retired deny rule. It's safe for the same reason: it only sets a timeout on a hook Entire wrote that has none, so nothing the user chose is changed.

Suggested shape:

- **Shared table.** Build the per-hook-type timeouts (command → timeout, with `SessionEnd` left out) from `entireSimpleHooks()` plus the pre-task and post-task commands. Change `setMissingTimeout` to take that table, so `installHookEntries` and the repair use the same values.
- **Repair method.** Add `RepairHookTimeouts(ctx) (bool, error)` on `ClaudeCodeAgent`. It adds the missing timeouts and changes nothing else:
