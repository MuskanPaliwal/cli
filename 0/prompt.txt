This is essentially a graceful abort.

  There is one subtle problem: Git can exit successfully after EOF because it successfully aborted.
  We must not interpret that as “the CAS succeeded.” Therefore cmd/entire/cli/gitrepo/ref_cas.go:175
  now checks:

  if tx.canceled.Load() {
      return fmt.Errorf(
          "wait for git update-ref transaction: %w",
          tx.ctx.Err(),
      )
  }

  So the two outcomes stay distinct:

  normal EOF after commit/abort → success
  EOF caused by cancellation   → context.Canceled this is a bit unclear
