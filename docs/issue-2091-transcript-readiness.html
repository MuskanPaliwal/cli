When is Claude's transcript safe to read?

The current Stop hook waits about half a second for a signal that never arrives, then reads the file through a separate open. The proposed fix should be faster, but the important part is making the bytes Entire validates identical to the bytes it stores.

Race 1: valid JSON can still be the wrong turn

Use the buttons to compare the tempting shortcut with the actual failure. The dangerous detail is that a complete JSON prefix proves syntax, not freshness.

{"type":"user","message":{"content":"Fix the bug"}} {"type":"assistant","message":{"content":[{"type":"text","text":"Working on it"}]}} {"type":"assistant","message":{"content":[{"type":"text","text":"Fixed it

Gut check: if the third line does not exist yet, the first two lines are still perfectly valid JSONL. A two-poll check can therefore return a clean but semantically incomplete transcript.

Race 2: validation and consumption read different states

Current contract

PrepareTranscript(path) validates file state A returns nil ReadTranscript(path) opens path again consumes file state B

Between A and B, Claude can append, truncate, or replace the file. The consumer has no handle, size, identity, or bytes from the validated state.

→

Proposed contract

ReadTurnEndTranscript(event, offset) opens one candidate state reads to an exact size bound validates current-turn JSONL returns []byte snapshot all consumers use snapshot

Later writes cannot mutate the returned bytes. A short read caused by truncation becomes an error. Appends after the bound are intentionally excluded.

There is a second re-read during checkpoint finalization

The main Stop handler first copies a transcript snapshot, but finalizeAllTurnCheckpoints later reopens Claude's live path. It can replace provisional checkpoint content with a different, unvalidated state. The fix must pass the same in-memory snapshot into finalization.

Recommended flow

1

Receive Stop

Parse last_assistant_message from Claude's hook payload.

2

Anchor the turn

Load the line offset measured before this prompt. A measured zero is valid; an unmeasured zero fails closed. This prevents a duplicate “Done.” from an older turn matching.

3

Observe and read

After two unchanged observations, read exactly that file identity and size into memory.

4

Validate

Require valid JSONL and the expected final assistant response after the turn offset.

5

Own the bytes

Write Entire's copy once. Metadata, tokens, offsets, and finalization all consume that snapshot.

Three designs compared

Reject alone

Two polls + valid final JSON

  • Likely 50 to 100 ms on the healthy path.
  • Rejects a half-written final object.
  • Accepts a complete prefix that lacks the current turn.
  • Leaves the separate-read race open.
Necessary

Validated immutable snapshot

  • Consumed bytes equal validated bytes.
  • Closes append, truncate, and replacement races for the snapshot.
  • Still cannot prove that a later complete record will not appear.
Recommend

Snapshot + current-turn watermark

  • Uses Claude's Stop payload as the freshness proof.
  • Uses the turn-start offset to disambiguate repeated text.
  • Returns exact bytes and makes timeout observable.
  • Keeps OpenCode's materialization contract unchanged.

Regression coverage that tests properties, not luck

Pure readiness tests

  • Complete JSONL with the current-turn watermark
  • Partial trailing JSON record
  • Repeated assistant text before and after the turn offset
  • Same-size replacement with a new file identity
  • Snapshot bytes remain unchanged after a late append

Polling and lifecycle tests

  • Continued growth resets readiness
  • A pause followed by writes cannot return early
  • Missing, stale, timeout, and cancellation paths
  • Finalization reads Entire's owned snapshot
  • Writer goroutine errors are reported, never silently ignored

Timing discipline: use injected poll settings and synchronization channels. Keep wall-clock assertions broad. The measured before value is about 510 ms; the expected healthy-path shape after the change is one poll interval, but correctness tests should not assert a fragile millisecond target.

Decision before implementation

The main compatibility choice is what to do when Claude does not provide last_assistant_message. Versions before 2.1.47 need the existing 500 ms quiet window because Entire does not currently enforce a minimum Claude version.

Decision: preserve that legacy heuristic without shortening it. Modern marker mismatch, timeout, cancellation, or an unmeasured turn boundary still fail closed and return no snapshot.
