Worth addressing

4. Doctor contradicts itself (plausible, not run).
CheckHookConfig ignores timeouts. On an old config, doctor prints "hook config: OK" and then "MISSING TIMEOUTS" in the same run, and entire status never mentions missing timeouts.

5. Old command shapes get no timeout (plausible, not verified).
The repair matches hooks only by today's exact command string. Hooks written in an older command shape get nothing from doctor; only entire enable fixes them.

6. Duplicated read/write code.
RepairHookTimeouts repeats the settings read/parse/write steps that loadRawClaudeSettingsForInstall, parseHookType/marshalHookType and writeClaudeSettingsFile already do. It could reuse them.

Low priority

- Explicit "timeout": 0 is overwritten. The code can't tell 0 from a missing value, so a user can't opt out of the timeout. Rare in practice.
- Mixed-case keys get written twice. A key like "Timeout" is decoded into the field and also kept as an extra field, so it appears twice on write-back. This is an edge case, but deleting known keys case-insensitively would fix it.
- Doctor reorders keys in the whole settings file. True, but writeClaudeSettingsFile on the install path already does the same, so this PR doesn't introduce it. The new part is that doctor now does it without asking.
